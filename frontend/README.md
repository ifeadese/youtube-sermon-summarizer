# Frontend — Sermon Summarizer

A single-page React app (built with Vite). Paste a YouTube URL, click Generate,
and the reflection streams in below — generated by Gemini directly from the
browser using the visitor's own API key. There is no backend.

## How it works

- `src/lib/gemini.js` — the Gemini client. `validateKey` checks a key with a
  zero-token request; `generateReflection` streams a reflection for a public
  YouTube URL (the Interactions API takes the video URL as input, so there is
  no transcript step). The key goes only in the `x-goog-api-key` header to
  `generativelanguage.googleapis.com`.
- `src/prompt.js` — the writing prompt (see `../docs/PROMPT_LOG.md`). It ships
  in the bundle and is therefore public; that is an accepted trade-off.
- `src/lib/keyStore.js` — where the key lives: `localStorage` when the visitor
  ticks "Remember on this device", `sessionStorage` otherwise, memory if
  storage is blocked. Never sent anywhere but Google, never logged, never in
  analytics.
- `src/ConnectGeminiModal.jsx` / `src/ProviderChip.jsx` — the connect dialog
  and the top-bar status chip.

## Setup

```bash
cd frontend
npm install
cp .env.example .env   # optional — only needed for GA
```

## Run

```bash
cd frontend
npm run dev
```

Vite serves the app on `http://localhost:5173`. Generate works locally with no
other services: connect a Gemini key in the dialog and go.

## Build

```bash
npm run build      # outputs static files to dist/
npm run preview    # serve the production build locally
```

## Tests

```bash
npm test           # run the Vitest suite once
npm run test:watch # re-run on change
```

Tests use Vitest + React Testing Library (jsdom). The Gemini client is tested
against mocked `fetch` responses (SSE streams, error bodies captured from the
real API); the app tests mock the client module and cover the connect flow,
streaming, cancel, error paths, and the guarantee that the key never appears in
an analytics payload.

## Live spike

`scripts/gemini-spike.mjs` runs the real API through the shipped client from
Node, to check the wire format after an API change:

```bash
# put GEMINI_API_KEY=... in frontend/.env.local (gitignored) first
node scripts/gemini-spike.mjs https://www.youtube.com/watch?v=VIDEO_ID
node scripts/gemini-spike.mjs --validate-only
node scripts/gemini-spike.mjs <url> --bad-key   # error-path check
```

It prints event names, usage and the first 200 characters of text; it never
prints the key.

## Requirements

Node `^20.19.0 || >=22.12.0` (pinned in `package.json` `engines`, matching the
Vite 8 toolchain).

## Fonts

The UI uses **Fraunces** (serif display) and **Inter** (sans body), self-hosted
via [`@fontsource`](https://fontsource.org/) and imported in `src/main.jsx`.
They're bundled into `dist/` at build time, so there are **no third-party font
requests** — the app renders identically offline and under the strict CSP.

## Deploy (Vercel)

The app is a static site.

1. New Vercel project → import this GitHub repo.
2. Set **Root Directory = `frontend`**. Vercel auto-detects the Vite preset
   (build `npm run build`, output `dist/`).
3. Optional: set **`VITE_GA_MEASUREMENT_ID`** for Google Analytics.

`vercel.json` adds a Content-Security-Policy whose `connect-src` allows only
Google's API host, FormBold (contact form), Google Analytics and Vercel's
preview toolbar. If you add a new external service, add its origin there or the
browser will block the request.
